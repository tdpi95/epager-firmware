# Test vectors

Generated by `tools/codegen/vectors.py` from the cases defined there; every expected result is recomputed by the Python reference (`tools/epager_proto`) before a file is written. Never edit these files by hand: change the cases, regenerate, and commit together with the contract change.

Each file has `contract_version`, `description` and `scope`:

- `app+board`: the Dart implementation in `epager-app` **and** the C library must pass.
- `board`: board-only behaviour (the app may ignore it).
- `app`: app-only behaviour (the board never sees it).

| File | Scope | What it checks |
| --- | --- | --- |
| `messages.json` | app+board | Header/TLV decoding, validation order and status, canonical encoding. `logical` is the decoded form (protocol.md §2.3); unless `decode_only`, encoding `logical` must give exactly `hex`. |
| `segments.json` | app+board | `split`: segments a sender must produce. `reassemble`: events a receiver must produce (including two `SEGMENT_ERROR`s for a bad FIRST mid-message, and a zero-length write while discarding). |
| `config_values.json` | app+board | Per-key config value validation for a board variant; `value` is the typed form. |
| `crc32.json` | app+board | CRC-32 known answers; implementations must also support incremental updates. |
| `text.json` | board | Display text normalisation (protocol.md §8). |
| `ancs.json` | board | ANCS Notification Source parsing, Control Point request bytes, Data Source reassembly, dates. |
| `transfer.json` | app+board | Transfer state-machine scenarios (protocol.md §7): install, resume after disconnect and after reboot, restart flag, bad offset, chunk past the end, CRC/SHA mismatch, invalid asset header, abort, oversize/no space, busy, paging, app icons (install, wrong size), firmware version/battery gates. The board must send exactly the expected messages; the app can replay its side (encode requests, decode answers). Computed by the reference board model `tools/epager_proto/transfer.py`. |
| `releases.json` | app | `manifests`: validity of firmware release manifests (`problem` null, `schema`, `duplicate_board_id` or `file_name`). `select`: the image the app offers, or the first refusal reason (releases.md). |
| `app_icons.json` | app+board | `ids`: the `app_icon` asset id of an app ID (SHA-256 rule, asset-formats.md); both sides compute it. `icons`: `mono1` icon files from pixel rows, for the app's encoder (the board's acceptance of the Paper file is in `transfer.json` `app_icon_install`). `removal` (board only, since 0.12.0): which icons are installed after an app is forgotten or evicted from the seen list. |
| `clock_faces.json` | app+board | Clock faces (since 0.15.0, asset-formats.md "Clock faces"): `faces` (named files), `parse` (a file, the board's limits and the asset id: accepted with its summary, or `IMAGE_INVALID` / `TOO_LARGE`), `options` (stored `(id, value)` pairs resolved against a face, and packed again), `eval` (what every element of a face draws for an option setting and a data snapshot) and `gallery` (`gallery.json` manifests against `clock-face-gallery.schema.json`). The reference is `tools/epager_proto/clockface.py`; an app that previews faces implements `parse`, `options` and `eval`, one that only installs them needs `gallery` and the container check. |

Running them: firmware side `ctest --test-dir build/host` (see AGENTS.md); Python reference `tools/.venv/bin/pytest tools`.
