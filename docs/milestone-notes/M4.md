# M4: ESP-IDF project for the Paper (2026-10-11)

Everything below was done without the board: it builds and the host-side parts are tested, but **no line
of firmware has run on hardware**.

- **Done:**
  - `variants/paper`: ESP-IDF 5.5.5 project (`CMakeLists.txt` with `EPAGER_BOARD`, `partitions.csv`,
    `sdkconfig.defaults` with a reason per option, `sdkconfig.signed` overlay for option A,
    `version.txt` 0.1.0, `dependencies.lock`). `app_main` takes the power latch, initialises power
    management, NVS, mounts the `assets` partition (LittleFS), brings up the NimBLE host (not advertising),
    wires the portable core (RAM `kv_mem` stand-in for NVS) and the LVGL UI to the board, runs one
    loop (core tick + `ui_service`), and logs version, init results, free heap and stack headroom. No
    notification content is logged.
  - `boards/waveshare_s3_epaper_154`: every pin in `ws154_pins.h` with its schematic net and polarity;
    `board.c` (profile, power latch and rails, polled keys, battery ADC); `ws154_epd.c` (SSD168x display
    driver written from the command set, see D38).
  - `components/power` (esp_pm DFS + automatic light sleep, PM locks); `components/board_api`: optional
    `init` in `board_profile_t` and `board_util.h` (LiPo curve, key detector: pure, host-tested);
    `components/core/Kconfig` (`EPAGER_FEATURE_*`, `EPAGER_LOG_CONTENT`); `ui_common` builds under
    ESP-IDF with `lvgl/lvgl` 9.5.0 and the shared `lv_conf.h`, plus gated feature placeholders.
  - `tools/lvgl_conf_check.py`, `tools/feature_check.sh`; `docs/adding-a-board.md`, `docs/recovery.md`;
    hw-checklist items 7-14; PLAN D36-D41, §2 facts, §5 final partition table; AGENTS.md updated.
  - Read the **schematic and the PICO-1 datasheet**: pins and polarities confirmed (and the demo's pins
    were all correct), plus four facts that change the design: **no 32 kHz crystal for the SoC**,
    **no VBUS/charge pin** (external power unknown), **octal PSRAM** (GPIO33-37 reserved), and the
    **power latch polarity** (GPIO17 high = battery connected).
- **Verified (how):**
  - `idf.py build` from a **clean directory: 0 warnings in the whole log** (IDF and LVGL included; our
    components compile with `-Wall -Wextra -Werror -Wshadow -Wstrict-prototypes`). Signed build
    (`-DEPAGER_SIGN=ON`, throwaway dev key) also builds with 0 warnings; the signature block verifies
    with `espsecure.py signature_info_v2` / `verify_signature`.
  - Effective sdkconfig read back: 8 MB flash, octal PSRAM, NimBLE 1 connection / 3 bonds / SC / NVS bonds / MTU
    517, BLE modem sleep on the main XTAL, PM + tickless idle, app rollback, no coredump, USB Serial/JTAG
    console, custom partition table.
  - Size report (below). Partition table checked by IDF's `check_sizes.py` (bootloader and app fit).
  - **Feature gating:** `tools/feature_check.sh --prove`: with the four `EPAGER_FEATURE_*` options off
    0 symbols (and 0 map lines) match; with them on, 4 symbols (13 map lines) match, so the check can fail.
  - **LVGL configuration:** the managed `lvgl__lvgl` tree is byte-identical to the SHA-256-pinned host
    archive (`diff -rq`: only registry metadata differs). `lvgl_conf_check.py` compares all 791 `LV_*`
    macros after expansion: it first found 14 differences, four of them real (D37), now pinned; 6 explained
    differences remain (include style, examples/demos, assert header, drive letter, `LV_CONF_PATH`).
  - Host: `ctest` 9/9 under ASan+UBSan (new `test_board_api`, 9 tests; two deliberate mutations of
    `board_util.h`, a short press after a long press and no debounce, failed 3 and 2 tests); `pytest tools`
    230 passed with the 14 golden images unchanged after the `lv_conf.h` changes; coverage of the portable core
    98.1 %; `contract_check.py` OK; `xtensa_check.sh` warning-free; `font_gen.py` / `icon_gen.py --check`.
  - LVGL heap peak across all UI host tests (longest text, 8 cards, icons): 24.4 KB, so the static pool was
    cut from 96 KB to 48 KB (D37); DIRAM static use fell from 78 % to 64 %.
- **Size report (ESP-IDF 5.5.5, `-Os`):**
  - Image: **657,520 B unsigned** (0xA0870), **724,992 B signed** (+67 KB: signature block and verification
    code, padded). Bootloader 19,824 B (signed 19,872 B).
  - Slot: **3 MiB x 2** (kept from PLAN §5): 4.8x the unsigned and 4.3x the signed image; the 1.4x rule allows a
    final image of 2.14 MiB. **Leftover asset space** 1,920 KiB (1,966,080 B total LittleFS; the firmware logs
    the real number at boot). Flash map: bootloader 32 KiB reserved, table 4 KiB, NVS 64 KiB, otadata 8 KiB,
    phy 4 KiB, 16 KiB unused, 2 x 3 MiB, assets 1,920 KiB = exactly 8 MiB.
  - Segments: flash code 441.9 KB, flash rodata 105.3 KB, DIRAM 218.9 KB of 341.8 KB (64 %: `.bss` 125 KB
    including the 48 KB LVGL pool and 53 KB in `main`).
  - Largest archives: LVGL 158 KB, BT controller libs 88 KB + `bt` (NimBLE) 82 KB, `main` 54 KB (RAM
    stand-ins), `esp_app_format` 50 KB, `ui_common` 43 KB (fonts, icons), libc 40 KB, LittleFS 22 KB, our
    protocol/core/transfer/pipeline/config about 7.6 KB (linked so far).
  - **Estimate, not a measurement:** the image will grow by about 30 KB (rest of the portable core: 37.5 KB
    fully linked per `xtensa_check.sh`), BLE service + ANCS client, OTA sink, the real UI and fonts: roughly
    1 MB in total, 3x headroom in a 3 MiB slot. Re-measure in M5 and M6.
- **Not verified:**
  - **Everything on the target:** boot, USB console, PSRAM, the e-paper driver (controller model, every
    command value, orientation, partial waveform quality), power latch behaviour when the PWR key is released
    early, battery ADC accuracy, the LiPo curve, key feel, LittleFS formatting at first boot, free heap and stack
    headroom (hw-checklist items 7-14). No QEMU boot test: Espressif's QEMU is not installed (a download, not
    asked for); it would only show boot, partitions and NVS, not BLE or the panel.
  - The SSD1681 controller datasheet was not read.
  - Whether the bootloader refuses an unsigned or wrong-key image at boot: read from the source (it does
    not in option A) but not run.
  - Internal RAM left for NimBLE and controller heap (allocated at runtime; the boot log prints it).
  - `flash` over USB (no board).
- **Decisions / contract changes:** D36-D41 in PLAN §4 (project structure and warnings, LVGL config and pool
  size, display driver from the command set, power/inputs, option A as the source reads, LittleFS 1.22.1);
  PLAN §5 final. **No contract change.**
- **Findings the user should know:**
  - The **Waveshare demo repo has no licence file**, so no code or waveform tables were copied; the driver uses
    the controller's built-in waveforms and may need the custom-LUT fallback (hw-checklist item 7).
  - **Option A does not check signatures in the bootloader:** an unsigned USB-flashed image boots but can never
    accept OTA; boards must be flashed with a signed build (`docs/recovery.md` §4).
  - **External power cannot be read** (no VBUS pin), so the 30 % OTA gate applies even when charging.
  - **No 32 kHz crystal for the SoC:** BLE light sleep uses the main XTAL (more idle current; measure).
  - **ESP-IDF Kconfig defaults changed rendering-relevant LVGL options** (colour-mix rounding, break
    characters): without `lvgl_conf_check.py` the device would have drawn differently from the golden images.
- **Follow-ups for M5:** split the core and UI tasks with a queue (they share the main task now; the stack
  is 8 KB with `cfg_store`'s `handle_set` alone at 1 KB; see the headroom log line); NVS-backed `kv_storage`
  (replaces the `kv_mem` stand-in, 53 KB `.bss` in `main`), and decide the NVS erase policy so a version
  change does not drop the bonds (`init_nvs` erases today); `epager-XXXX` name from the BT MAC; button
  callbacks run in the `esp_timer` task and must only queue; the `blob_storage` adapter over LittleFS and the
  UI/core locking (M3 follow-up) are M6; a `bootloader_before_init` latch hook if checklist item 8 needs it;
  re-measure free internal heap with NimBLE connected and the LVGL pool with the real UI.
