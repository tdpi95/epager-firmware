# M1: Contracts + portable protocol library + PC tests (2026-10-11)

- **Done:**
  - Contract 0.1.0 in `contracts/`: `protocol.md` (written first), `registry.json` + `registry.schema.json`,
    `gatt.json` (UUID base `a08aXXXX-0c0a-4214-8b47-6c1925da5fca`), generated `schemas/` (8 files) and
    `reference.md`, `asset-formats.md`, `CONTRACT_VERSION`, `CHANGELOG.md`, `compatibility.md`.
  - Vectors (`contracts/test-vectors/`): messages (120 cases: 60 valid, 6 decode-only, 54 invalid),
    segments (5 split, 15 reassembly), config_values (37), text (31), ancs (7 Notification Source,
    3 request, 13 Data Source, 11 dates), crc32 (5).
  - Python reference `tools/epager_proto` and generators `tools/codegen/{gen,vectors}.py`; `tools/contract_check.py`.
  - C library `components/protocol` (portable C11, table-driven codec, segments, CRC-32, UTF-8, text
    normalisation, ANCS parsing/reassembly, config validation); builds as an ESP-IDF component or a host library.
  - Host tests `tests/host` (Unity + cJSON vendored from ESP-IDF 5.5.5): `test_vectors`, `test_unit`, `test_fuzz`.
  - Environment: installed cmake 3.30.2 + ninja 1.12.1 via `idf_tools.py`; created `tools/.venv`; `git init`.
- **Verified (how):**
  - `ctest`: 3/3 pass with ASan+UBSan, every vector case passes; the runner was shown to fail on four
    deliberately corrupted vectors.
  - Fuzz: 1,000,000 iterations per target (message parse, text, segments, ANCS) clean under ASan/UBSan.
  - `pytest tools`: 127 pass, including the text reference matching real Unicode NFC for every
    composable letter in the renderable set (in canonical and reversed mark order).
  - `contract_check.py` OK; shown to fail on a schema-violating vector and on a platform include in portable code.
  - Cross-compiled the library with xtensa-esp32s3-elf-gcc 14.2 (`-Os -Wall -Wextra -Werror -Wpedantic`):
    no warnings, ~16 KB text (10.7 KB of it generated tables and field names).
  - `-Werror -Wpedantic` build on host GCC 13.3.
- **Not verified:** the Dart app has not run the vectors yet; nothing tested over BLE or on phones;
  ANCS byte layouts come from Apple's spec text plus ESP-IDF's example (the spec's figures are images);
  whether iOS lists the board via the ANCS solicitation; whether Android filters on the service UUID in
  the scan response.
- **Decisions / contract changes:**
  - Contract 0.1.0 created (D2-D5, D19).
  - Added D22 (Python reference generates the vectors).
  - Text rules gained `removed_ranges` (soft hyphen, zero-width characters, BOM) and `compose_ranges`.
    The second one fixes a bug found by the NFC cross-check: an intermediate composite (U+0228) was
    missing, so `E` + U+0306 + U+0327 did not compose to `Ḝ`; a vector now covers it.
  - Transfer scenario vectors move to M2, alongside the state machine they test.
- **Follow-ups:** the asset font format is still provisional (decided with the Paper UI). The app
  team can start on the contract now (Dart codec + vectors).
